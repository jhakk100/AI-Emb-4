# 임시통합

기존 `1-standby`, `2_face`, `3_embedding`, `4_db_authentication`을 한 카메라와 한 UI로 연결한 실험용 통합본입니다. 소스·설정·테스트·라이선스는 Git으로 공유합니다. `.venv`, 얼굴 DB와 임베딩 등 `data/`, 실행 로그, 다운로드 모델 파일은 `.gitignore`에서 제외합니다.

## 실행

처음 다운로드한 경우 Python 3.12 이상과 Tkinter를 설치한 뒤 **`setup.bat`을 한 번 실행**하세요. `.venv` 생성, `requirements.txt` 패키지 설치, YuNet/SFace 모델 다운로드와 SHA-256 검증을 수행합니다. 첫 설치에는 인터넷이 필요합니다. 이후 **`run.bat`을 더블클릭**한 뒤 **카메라 시작**을 누르세요. 기본 카메라 번호는 0입니다. 이미 설치를 마친 로컬 환경에서는 바로 `run.bat`을 실행하면 됩니다. 얼굴 DB는 실행할 때 새로 생성하며 등록 데이터는 PC별로 관리합니다.

하나의 창에서 카메라를 공유합니다.

- **인식·기록**: 대기 조건을 통과하고 등록 사용자 인증에 성공한 얼굴만 DB에 저장합니다. 미등록 얼굴·인증 실패·여러 얼굴·임베딩 오류는 저장하지 않습니다. 기본 저장 간격은 1초이며 0.2~60초 범위에서 적용할 수 있습니다. 저장 판단과 화면 인증 결과에 동일한 인증 기준을 사용합니다.
- **사용자 등록**: 이름을 입력하고 등록 버튼을 누른 경우에만 사용자로 등록합니다. 한 사람의 선명한 샘플 15개를 모아 대표 임베딩을 저장합니다. 등록 취소·재등록·삭제가 가능합니다.
- **수집 기록**: 최근 8개 기록의 임베딩 생성 상태를 표시합니다. 행을 선택하면 저장된 얼굴 Crop을 확인할 수 있습니다. 화면에 8개만 표시할 뿐 DB에는 계속 누적됩니다.

카메라 중지 또는 창 닫기를 누르면 카메라를 해제합니다. 실행만으로 카메라가 자동으로 켜지지는 않습니다.

## 작동 모드와 문 상태

오른쪽 위에서 **연속 작동 / 1회 작동**을 선택합니다. 실제 문이나 GPIO를 제어하지 않고 UI의 텍스트·LED로 문 상태를 모의 표시합니다.

```text
1단계 대기 → 검출·임베딩 → 등록 사용자 인증 성공 → 인증된 얼굴 기록 저장
  → “문이 열렸습니다.” (3초)
  → “문이 닫혔습니다.” (1.5초)
  → 대기 조건과 이전 프레임 초기화 → 1단계 복귀
       연속 모드: 카메라를 유지하며 다음 인증 진행
       1회 모드: 카메라 해제 후 ‘카메라 시작’으로 재시작 대기
```

문 열림·닫힘 표시 중에는 추가 인증과 저장을 일시 정지합니다. 같은 얼굴을 보고 있어도 열림 타이머가 계속 연장되지 않으며, 다시 인증하려면 1단계 유지 시간 조건부터 확인합니다. 인증 실패 시에는 문을 열거나 DB에 저장하지 않고 계속 대기합니다. 모드 변경은 현재 문 닫힘 이후 동작에도 적용됩니다.

미리보기 위에 **현재 처리 단계**와 **1 대기 조건 / 2 검출·Crop / 3 임베딩 / 4 DB·인증** 상태를 표시합니다. RGB LED는 실제 GPIO 없이 UI에서 임시로 구현했습니다. 흰색 깜박임은 얼굴·카메라 대기, 노란색 깜박임은 대기 조건 확인, 파란색은 DB 저장 완료, 초록색은 인증 성공, 빨간색은 미등록 또는 오류, 보라색은 사용자 등록, 회색은 중지입니다. 1~4단계는 빠르게 반복되며 수집과 인증은 서로 다른 조건으로 동작합니다.

## 처리 구조

**1단계 절전 모드**는 `set1.json`의 해상도·FPS를 실제 통합 처리에 사용합니다. 기본값은 **320×180 / 5FPS**이며 YuNet 대기 조건 검사만 실행하고 SFace 임베딩·인증·DB 저장은 하지 않습니다. 조건을 통과한 다음 프레임부터 **640×480 / 최대 20FPS**로 전환합니다. 고해상도 프레임에서도 얼굴 조건을 다시 확인한 후 임베딩을 생성하므로 저해상도 Crop으로 인증하지 않습니다. 얼굴이 사라지거나 대기 조건을 잃으면 절전 모드로 복귀합니다. 문 닫힘 이후에도 유지 시간·해상도·FPS를 초기화해 절전 대기부터 다시 시작합니다.

카메라 장치에 해상도·FPS를 직접 요청하고, 장치가 해상도 요청을 지원하지 않는 경우에도 분석 프레임은 지정 해상도로 맞춥니다. 읽기 루프와 실제 추론 시작 간격을 모두 제한하므로 카메라 버퍼에서 프레임이 연속 반환되어도 분석이 5FPS를 초과해 몰아서 실행되지 않습니다. UI에서 **분석 해상도·목표/실측 FPS**와 **카메라 원본 해상도·드라이버 보고 FPS**를 따로 볼 수 있습니다.

현재 웹캠 검증에서는 320×180 요청에 640×360 프레임을 반환하고 FPS는 5로 보고했습니다. 분석은 320×180으로 축소합니다. 640×480 / 20FPS 요청과 다시 절전 설정으로 복귀하는 것도 확인했습니다. 소비 전력 자체를 측정한 결과는 아닙니다.

```text
공유 카메라
  → 1단계: 320×180 / 5FPS YuNet 조건 검사 (임베딩 중지)
  → 조건 통과 시 카메라/분석을 640×480 / 최대 20FPS로 전환
  → 2단계 YuNet 검출 및 고해상도 조건 재확인
  → 3단계 눈·코·입 정렬 + SFace 128차원 임베딩
  → 4단계 명시적으로 등록된 사용자와 비교하여 인증
  → 성공한 경우에만 간격에 따라 Crop+임베딩을 하나의 DB 기록으로 저장
  → 문 열림 → 문 닫힘 → 1단계 복귀

사용자 등록 탭 → 명시적 등록 시작 → 품질 조건을 통과한 15개 샘플
             → 대표 임베딩 생성 → DB people에 저장
```

**인증된 얼굴만 저장하며 저장 간격은 최소 간격입니다.** 문 열림·닫힘 대기 중에는 추가 저장을 멈추므로 실제 기록 수는 1초당 1장보다 적을 수 있습니다. 신규 사용자 등록 중에는 임베딩 샘플을 메모리에 모아 등록을 완료하지만, 미등록 얼굴의 Crop을 수집 기록에 자동으로 넣지는 않습니다.

Crop은 박스나 이름을 그리기 전의 활성 분석 프레임에서 추출합니다. 분석 프레임은 카메라 입력의 비율을 유지해 640×480에 맞추며 영상과 Crop은 좌우 반전된 같은 좌표계를 사용합니다. 절전 분석 프레임은 저장하지 않습니다.

DB 저장 함수도 등록 사용자 일치와 대기 조건 통과를 다시 검사합니다. 인증된 Crop과 임베딩은 한 트랜잭션으로 함께 저장하며, 임베딩 생성 실패 시 Crop을 별도로 남기지 않습니다. 저장은 UI 표시 전에 완료합니다.

## DB

`data/faces.sqlite3` 하나에 SQLite로 저장합니다. 외부 DB 서버는 필요하지 않습니다.

| 테이블 | 저장 내용 | 생성 시점 |
| --- | --- | --- |
| `observations` | 관측 ID, UTC 시각, 입력 장치, 박스 좌표, 검출 신뢰도, JPEG Crop BLOB, 임베딩, 통과 여부, 인증 사용자 이름·유사도·기준값 | 인증 성공 후 저장 간격이 지난 경우 |
| `people` | 이름, 대표 임베딩, 등록 샘플 수, 갱신 시각 | 사용자가 등록을 완료한 경우 |
| `metadata` | 임베딩 모델 ID | DB 초기화 |

**수집 기록이 쌓여도 자동으로 사용자 등록이나 대표 임베딩 갱신을 하지 않습니다.** 등록 사용자를 삭제해도 관측 기록은 유지합니다. 기존 `FaceStore` JSON 기능은 원본 테스트 호환을 위해 남아 있지만 통합 UI는 SQLite를 사용하며 기존 JSON을 자동으로 가져오지는 않습니다.

기록은 향후 인식률 개선에 사용할 수 있도록 Crop과 임베딩을 연결해 둡니다. 정답 라벨링, 오인식 피드백, 데이터 분리, 기준값 재평가, 자동 학습·모델 업데이트는 아직 구현하지 않았습니다. 따라서 누적만으로 인식률이 자동 향상되지는 않습니다. 현재 앱에는 생체 확인 기능도 없습니다.

모든 기록은 로컬에 저장됩니다. 자동 삭제나 용량 제한은 없으므로 계속 실행하면 DB 크기도 증가합니다. 전체 영상은 저장하지 않습니다.

## 주요 파일

- `app.py`: 단일 Tkinter UI, 카메라 작업 스레드, 등록·인증·기록 보기
- `pipeline.py`: 검출 → 임베딩 → 대기 조건·사용자 인증 → 성공 얼굴만 저장
- `capture_control.py`: 절전/활성 카메라 설정, 정확한 분석 해상도, FPS 제한
- `door_cycle.py`: 문 열림·닫힘 시간 및 연속/1회 모드 상태 전환
- `status_panel.py`: 임시 RGB LED 및 1~4단계 상태 표시
- `standby.py`, `set1.json`: 1단계 대기 조건과 유지 시간 검사
- `detection.py`: 2단계 검출·좌표 복원·Crop·한글 경로 이미지 입출력
- `face_core.py`: 3단계 정렬·임베딩·등록 품질 검사
- `database.py`, `authenticate.py`: 4단계 SQLite 저장과 등록 사용자 비교
- `evaluation.py`, `similarity.py`: 기존 FAR/FRR·유사도 평가 도구
- `models.py`, `licenses/`, `THIRD_PARTY.md`: 모델 다운로드·해시 검증·라이선스

대기 설정은 `set1.json`, 인증 기준은 UI 슬라이더에서 조절합니다. `set1.json`의 fps/resolution·유지 시간·비율·신뢰도 설정은 통합 파이프라인의 절전 모드에도 적용됩니다. 설정 파일 변경은 앱을 재실행하면 반영됩니다.
