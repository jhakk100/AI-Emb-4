# 단계별 점검 요약

## 1단계 — 준비 확인

- 준비 여부만 확인하고 카메라를 닫는다.
- 영상·ROI는 폐기하고 **준비 완료 신호만** 2단계에 전달한다.
- 위 동작은 정상 설계다.
- 수정할 점: 현재 clear 출력 후 카메라를 닫음 → **카메라 종료 후 clear 출력** 순서로 변경 필요.

## 2단계 — 얼굴 촬영·crop

- 카메라를 새로 열고 촬영용 해상도·FPS를 설정한다.
- crop만 반환해 **얼굴 좌표·눈코입 특징점·검출 점수**가 다음 단계에 전달되지 않는다.
- 여러 얼굴 중 인증 대상을 고르는 규칙이 필요하다.
- 창 표시·파일 저장은 테스트용으로 분리한다.

## 3단계 — 임베딩 추출

- 2단계에서 검출한 얼굴을 다시 검출하는 중복이 있다.
- **얼굴 정렬 + SFace 임베딩 추출** 중심으로 역할을 정리한다.
- 자체 JSON 저장·코사인 인증은 4단계와 중복된다.
- 등록 때만 크기·선명도를 검사한다. 인증 때의 품질 검사도 필요하다.

## 4단계 — DB·최종 인증

- 3단계 JSON과 4단계 SQLite가 분리돼 있어 등록 정보가 공유되지 않는다.
- 3단계 NumPy 배열을 그대로 받으면 거부한다. 입력 형식을 맞춰야 한다.
- DB 초기화 누락·데이터 손상 시 예외 처리가 필요하다.
- 임베딩 차원·모델 버전·재등록 정책을 통일해야 한다.

## 통합 시 정할 것

- **함수 통합이 없음**: 이미 알고 있는 통합 예정 사항.
- 2→3의 좌표·좌우 반전·데이터 전달 형식 통일.
- 인증 실패 후 재촬영·재시도·대기 복귀는 별도 제어부가 담당.
- 4단계가 2·3단계를 직접 제어할 필요는 없다.
- 생체 확인은 별도 기능이 필요하다.

## 검증 결과

- 3단계 단위 테스트 15개 통과.
- 제공 사진의 2단계 crop → 3단계 검출 통과.
- DB 분리·NumPy 입력 거부·DB 예외는 재현됨.
- 수치 경계 문제: 큰 입력에서 정규화 영벡터 또는 코사인 NaN 발생.
- 전체 연동·Pi·생체 확인은 미검증. 소스 수정 없음.
