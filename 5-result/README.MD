# 4방향 얼굴 grid + 통합 3D 모델 등록·인증

등록과 인증은 별도 처리부로 실행합니다. 하나의 카메라는 `CameraSession`이
소유하고, FHD 등록 단계와 인증 단계를 동시에 실행하지 않습니다.
`5-result.py`는 인증 후 출입 결과 처리에만 사용합니다.
이번 변경은 `5-result`에 적용하며 `6. rasberry pi`는 별도 실행본입니다.

기본 자세 보정은 **종학**입니다. 사용자가 설정한 5개 측정값과 좌표 안정화
설정을 `stages/pose_presets/jonghak.json`에 원본 정밀도로 보존했으며,
`stages/pose_defaults.json`이 이 프리셋을 선택합니다. 테스트 도구와 인증이
이 기본값을 예전 각도 기록으로 등록된 얼굴에 사용합니다. 수동 등록에는 보정 단계가 없고,
수동 등록 얼굴의 인증은 등록 Mesh에 저장된 방향을 사용합니다. 임시 P 키 보정을 새로 저장해도
이 이름 있는 기본 프리셋은 자동으로 덮어쓰지 않습니다.

이 이름은 **각도 보정 프리셋 이름**입니다. 이 값만으로 얼굴을 등록하거나
인증하지 않습니다. 실제 얼굴 grid와 통합 모델은 이름을 지정한 12장 등록에서
만듭니다. 사진이나 임베딩 없이 각도만으로 얼굴 모델을 생성하지 않습니다.

## Windows 실행

처음 설치는 `setup.bat`, 이후 실행은 `run.bat`입니다. 가상환경과 모델 다운로드는
기존 방법을 사용합니다. 앱을 열고 **카메라 시작 → 옵션 → 사용자 등록**으로 이동하세요.
Python 3.12 이상을 사용하는 기존 Windows 실행 환경을 기준으로 합니다.

1. 카메라 영상이 나오면 이름을 입력하고 등록을 누릅니다.
2. 화면의 화살표에 따라 **정면 → 위 → 화면 왼쪽 → 화면 오른쪽**을 봅니다.
3. 얼굴을 중앙 타원에 맞추고 **P 키** 또는 **수동 촬영 (P)** 버튼을 누릅니다.
   현재 방향에서 3장이 채택되면 다음 방향으로 넘어가며 총 12장을 찍습니다.
4. 12장을 모두 모은 뒤 **방향별 grid 4개와 통합 3D 모델 1개**를 만들고,
   사진·Mesh·임베딩과 한 번에 DB에 저장합니다.
   **등록 완료 · 나가기**를 눌러 등록 단계를 끝냅니다.
5. 인식·기록 탭에서는 무작위로 요청한 서로 다른 두 방향을 보고 인증합니다.

셔터를 누르면 다음 FHD 영상 한 장을 확인합니다. 얼굴 한 명의 중심이 타원 안에 있어야
하며, 사진이 선명하고 같은 사람인지 검사합니다. 고개 각도는 사용자가 안내를 보고
맞춥니다. 등록에는 각도 판정, 자세 유지 시간, 촬영 제한 시간이 없습니다. 얼굴이
없거나 위치·화질이 맞지 않으면 진행 수를 유지하고 같은 사진을 다시 찍을 수 있습니다.
콘솔의 `integrate.py enroll --name 이름`도 P 키 미리보기를 엽니다.

등록된 이름을 선택하고 **등록한 grid / 통합 3D 모델 보기**를 누르면,
방향별 4개 형상과 하나로 합친 모델을 별도 탭에서 확인할 수 있습니다.
통합 모델은 **468개 정점·852개 삼각형**으로 이루어지며 같은 모델을
세 각도로 투영해 표시합니다. 촬영 직후 미리보기에도 Mesh 연결선을 표시합니다.

카메라는 시작할 때 **1920×1080 FHD / 목표 30 FPS**로 엽니다. 대기·인증·등록
사이에서 카메라 설정을 다시 적용하지 않습니다. 대기 미리보기에서도 FHD로
영상을 받고, YuNet 대기 검사는 **320×180 / 초당 최대 5회**만 실행합니다.
실제 카메라 속도는 장치가 지원하는 설정에 따라 달라집니다.

등록 버튼을 누르면 별도의 **얼굴등록단계**에 진입합니다. FHD 촬영 원본으로
12장 등록과 DB 저장을 진행하고,
완료 후 나가기를 누를 때까지 절전 대기나 인증 단계로 넘어가지 않습니다. 인식·기록/수집 기록
탭, 작동 모드와 인증 기준 변경도 잠깁니다. 탭 전환만으로 등록을 취소하지
않으며, 명시적인 등록 취소·카메라 중지는 가능합니다.

다른 사람의 얼굴을 찍거나 전체 등록 검증이 실패하면 미완성 사진을 폐기하고
**등록 단계에 남아** `처음부터 다시 촬영` 또는 `등록 취소`를 기다립니다.
재촬영은 FHD를 유지하며 정면부터 새 12장을 모읍니다. 카메라 오류로 작업이
중지되어도 등록 화면 잠금을 유지하고, 재시작 시 등록용 FHD 카메라를 엽니다.
등록 중에는 출입 처리의 시작·진행·수동 개방을 막으며, 인증 결과나 이전 출입
완료 이벤트가 늦게 도착해도 등록 상태를 바꾸지 않습니다. 화면의 1~5단계
카드는 비활성 상태로 남고 별도의 등록 상태만 표시합니다.

카메라에서 실제로 받은 영상 크기도 검사합니다. 시작 직후의 저해상도 프레임은
버리고, 계속 FHD 미만이면 카메라 오류를 안내합니다. 저해상도 영상을
확대해서 FHD 등록 사진으로 사용하지 않습니다. 저장되는 얼굴 Crop은 FHD
원본에서 자른 영역이므로 얼굴 크기에 따라 Crop 자체의 크기는 달라집니다.

예전 방식으로 등록한 이름과 대표 임베딩은 삭제하지 않습니다. 다만 방향별
사진·Mesh가 없으면 인증을 통과시키지 않고 **4방향 재등록**을 안내합니다.
기존 5방향 15장 DB는 원본 사진·이름·대표 임베딩을 보존하며, 유효한 정면·위·좌·우
12장으로 4방향 grid와 통합 모델을 다시 만듭니다. 예전 아래 사진은 보존하되 인증에
사용하지 않습니다. 방향·형상·모델·보정 기준이 올바르지 않으면 변환하지 않고
재등록을 요구합니다. 새 등록은 12장으로 저장합니다. 기존 `directions=5` 제약의
모델 테이블도 원본 데이터를 유지하면서 4방향 저장을 허용하도록 변환합니다.
종학 기본 보정 파일의 측정값은 변경하지 않습니다. 예전 5방향 보정은 읽을 수 있지만
아래 판정은 항상 거절하며, 새로운 보정·테스트는 정면·좌·우·위 4단계로 끝납니다.

## 처리 순서

```text
1. FHD 1920×1080 / 목표 30 FPS 미리보기에서 방향 안내와 중앙 타원 표시
2. P 입력으로 다음 영상 한 장을 선택하고 YuNet으로 얼굴 수와 위치 확인
3. 선택한 사진에서만 SFace 임베딩과 Face Mesh 연산
4. 수동 촬영 방향, 사진 Crop, 임베딩, 원본·정규화 Mesh를 저장용으로 묶음
5. 방향별 3장을 정렬·평균해 grid 생성 → 4개 grid를 정렬·통합해 3D 모델 생성
```

등록 미리보기는 셔터가 들어올 때까지 영상과 안내만 표시합니다. YuNet은
640×480 내부 입력으로 얼굴을 검출하고 위치를 FHD 원본 좌표로 복원합니다.
임베딩과 Mesh는 같은 FHD 사진에서 계산합니다. 수동 등록 사진에는 측정 각도 대신
안내된 방향을 저장합니다.

## 인증

```text
정면에서 등록한 정면 Mesh와 임베딩으로 등록자 후보 확인
  → 정면·위·좌·우 중 서로 다른 두 방향을 무작위 선택
  → 현재 Face Mesh의 방향을 등록 당시 해당 방향의 Mesh와 비교
  → 자세 유지 후 같은 프레임을 고정하고 임베딩 계산
  → 같은 등록자의 같은 방향 샘플 3장과 각각 비교
  → 같은 방향의 대표 grid와 형상·상대 Z 비교
  → 4방향을 합친 통합 3D 모델과 형상·상대 Z 비교
  → 두 사진 모두 임베딩·개별 Mesh·방향 grid·통합 모델 조건을 만족하면 성공
  → DB에서 최신 등록 정보로 재검사하고 인증 사진 2장을 함께 저장
  → 기존 결과 처리 모듈로 성공/실패 전달
```

수동 등록 프로필의 방향 추정에는 예전 YuNet 각도 프리셋을 적용하지 않습니다.
절전 대기에서는 YuNet만 동작하고, FHD 인증이 시작되면 최대 초당 10회
Face Mesh를 계산합니다. 사진 두 장이 각각 방향별 사진·grid와 통합 모델 비교를
통과해야 인증되며, 기존 등록 DB를 그대로 사용합니다. 예전 각도 기록이 있는
등록은 기존 인증 경로를 사용합니다.

인증 영상에는 얼굴을 중앙에 맞추는 타원 가이드가 대기 중에도 표시됩니다.
요청 방향에 거의 맞으면 영상 아래에 필요한 동작 하나를 표시합니다. 예를 들어 왼쪽
회전은 맞고 상하 각도가 조금 부족하면 **턱을 살짝 들어주세요**가 나타납니다.
안내는 같은 보정이 잠깐 이어진 뒤 표시하고 약 0.6초 이상 유지해 순간적인 측정 변화에
깜빡이지 않게 합니다. 촬영하거나 인증이 끝나면 바로 지웁니다.
수동 등록 얼굴의 인증에서 상하 각도 허용폭은 정면 1.5배, 좌우 1.45배입니다.
정면을 통과한 자세의 상하 기준점은 기존 정면 허용 범위 안으로 제한합니다.
위 방향과 좌우 회전·기울기, Mesh 형상·상대 깊이·임베딩 비교에는 기존 기준을 적용합니다.
진단 로그의 `pitch_scales`에 실제 적용한 배율이 기록됩니다.

**10회 진단.** 카메라를 시작하고 **옵션 → 인식·기록 → 인증 10회 진단 시작**을 누릅니다.
결과가 나오면 한 회가 기록됩니다. 멈춘 경우 **이번 시도 중단으로 기록**을 눌러
현재 상태를 남기고, **다음 진단 시도 시작**으로 반복합니다. 이 기능은 인증 결과까지
확인하며 출입 동작은 실행하지 않습니다. 10회 이후 **일반 인증 재개**로 돌아갑니다.
저장 위치는 `logs/auth_diagnostics/auth-*.jsonl`입니다. 기록은 프레임, 카메라 지연,
대기 조건, 요청·판정 방향과 각도, 자세 유지, 형상·상대 깊이·임베딩 비교 점수,
화면에 표시된 자세 안내와 최종 결과를 포함합니다. 진단 파일에는 사진, 사용자 이름, Mesh 좌표, 임베딩 벡터를
넣지 않습니다.

**유사도 교차점.** **옵션 → 인식·기록 → 인증 시도 확인 · 유사도 교차점**에서 시도를
선택합니다. 당시 실제 인물을 별도로 확인한 경우 이름을 선택해 **선택한 등록자로
확인**을 누르거나 **미등록 타인으로 확인**을 누릅니다. 승인·거절 결과는 실제 인물
확인에 사용하지 않습니다. 혼자 시험할 때는 자신의 기록을 등록자로 확인합니다.
장치를 동작시키지 않는 10회 진단 기록도 같은 화면에서 확인할 수 있습니다.

`auth_attempts`에는 시도 결과, 첫 정면 비교 점수, 해당 시도의 임계값, 확인한 실제
인물을 기록합니다. 자세 또는 카메라 문제로 정면 점수가 없는 시도도 남습니다.
교차점 계산에는 점수와 실제 인물이 모두 확인된 시도를 사용합니다. 등록자는 자신의
점수가 본인 비교가 되고, 다른 등록자와의 최고 점수가 타인 비교가 됩니다. 미등록
타인은 등록 전체 중 최고 점수가 타인 비교가 됩니다.

현재 등록 구성에서 각 종류가 10건씩 모이면 최근 각 200건까지 사용해 오승인율과
오거부율이 가장 가까운 임계값을 계산합니다. 새 임계값은 다음 시도의 **첫 정면
임베딩 비교**부터 사용합니다. 방향별 임베딩과 Mesh 검사는 기존 기준으로 진행합니다.
등록 구성이 바뀌면 해당 구성으로 다시 표본을 모읍니다. **교차점 자동 적용**을 끄면
기본 기준을 쓸 수 있습니다. 화면의 오류율은 확인된 정면 비교 점수로 계산한 값입니다.

첫 사진만 통과해서는 성공하거나 관측 사진을 저장하지 않습니다. 두 사진의
DB 기록은 같은 `auth_session` 값으로 묶입니다. 비교와 두 기록의 저장은
하나의 트랜잭션에서 수행해 도중 등록 변경·삭제와 부분 저장을 방지합니다.
인증 사진을 시간 간격으로 하나씩 저장하던 설정은 화면에서 제거했습니다.

Mesh는 원본 478점의 `(x,y,z)`를 저장하고, 비교에는 얼굴 468점을 사용합니다.
영상 비율을 반영한 뒤 위치·눈 사이 크기를 정규화하고 강체 회전을 정렬하여
같은 방향의 등록 형상과 RMS 오차·상대 Z 오차를 비교합니다. 임의의 비선형
변형으로 얼굴 형상이나 깊이를 맞추지는 않습니다.

방향별 grid는 같은 방향의 3개 정규화 Mesh를 반사 없는 강체 정렬 후
평균해 만듭니다. 통합 모델은 4개 grid를 정면 grid에 정렬하고 정점별 중앙값을
구한 뒤 눈 사이 거리로 다시 정규화합니다. 원래 사진·Mesh도 함께 보관합니다.
방향 grid 또는 통합 모델 중 하나라도 불일치하면 인증 사진 두 장 모두 저장하지
않고 실패 처리합니다. 최종 DB 트랜잭션에서 두 모델을 다시 검사합니다.

**Mesh의 Z는 RGB 영상에서 추정한 상대 값입니다.** 이 비교는 실제 깊이 센서나
검증된 위조 방지 기능을 대체하지 않습니다. 기울인 사진·구부린 사진·재생 영상·
실시간 합성이 통과하지 않는지는 실제 카메라에서 별도로 검증해야 합니다.
방향별 grid와 통합 모델은 같은 Mesh 입력에서 나온 관련된 검사이며, 독립된
깊이 센서 두 개의 증거처럼 취급하지 않습니다. 전용 위조 탐지(PAD)는 이번에
추가하지 않았습니다.

## 설정과 오류 복귀

공통 촬영·형상 오차 설정은 `stages/guided_capture.json`에서 변경합니다. 기존 회전 검사 설정인
`liveness.json`은 새 설정으로 교체했습니다.

- 종학 기본값 활성 시: 저장된 5개 자세 기준과 방향별 거리로 판정합니다.
- 기본값 비활성화 시 기존 방식: 정면 ±12도, 좌우 15~35도, 상하 12~30도.
- 최소 3프레임·0.25초 유지, 촬영 간격 최소 0.4초.
- 인증 전체 25초·방향당 10초.
- 추적 간격 0.7초 초과, 여러 얼굴, 얼굴 소실, 급격한 위치 변화는 실패 처리.
- `yaw_sign`, `pitch_sign`으로 카메라에서 방향 안내가 뒤집히는 경우 보정.
- `mesh_limit=0.12`, `depth_limit=0.08`은 눈 사이 거리로 정규화한 시작값.
  실제 이용자·공격 샘플로 임계값을 검증해야 합니다.

명시적인 등록 취소·카메라 중지·오류 종료 시 미완성 샘플은 메모리에서 폐기합니다.
다른 얼굴의 임베딩이 섞이면 중단합니다. DB 저장 중 오류가 발생해도 기존
등록 정보가 부분적으로 교체되지 않도록 롤백합니다. 성공·실패 결과는
한 번만 전달하고, 화면 전환 후 예전 세션의 결과는 사용하지 않습니다.

## P 키로 4방향 보정하고 테스트

Windows에서는 **`test_pose.bat`**를 실행하세요. 기존 얼굴 앱의 카메라를 먼저
중지한 뒤 이 도구에서 카메라를 시작합니다. Pi 등에서는 같은 실행 환경에서
`python pose_test.py --camera 0`으로 실행할 수 있습니다.

현재 **종학 기본값과 좌표 안정화는 실제 등록·인증에도 적용**했습니다.
이 도구는 기본 프리셋을 우선 불러오며, P 키로 새로 기록한 임시 보정은
별도 `pose_calibration.json`에 저장합니다. 임시 보정 테스트는 현재 창에서
가능하지만 실제 앱의 이름 있는 기본값은 별도로 지정해야 변경됩니다.

1. `1920×1080 등록` 또는 `640×480 인증`을 선택하고 **보정 시작**을 누릅니다.
   카메라가 꺼져 있으면 자동으로 시작합니다.
2. 안내대로 **정면 → 왼쪽 → 오른쪽 → 위**를 차례로 봅니다.
   각 자세에서 잠시 멈춘 뒤 **P 키**를 누릅니다. 화면의 `P · 현재 자세 기록`
   버튼을 눌러도 같은 동작입니다. 최근 안정된 5프레임의 중앙값을 기록하므로
   숫자를 일일이 입력하거나 점을 드래그할 필요가 없습니다.
3. 방향별 기준이 **보정·테스트** 표에 쌓입니다. 너무 비슷한 자세, 흔들리는
   자세, 오래된/없는 영상은 기록하지 않고 P 키를 다시 누르도록 안내합니다.
   `이전 자세 다시`로 마지막 기록을 취소하고 다시 찍을 수 있습니다.
4. 5개를 완료하면 `stages/pose_calibration.json`에 각도와 카메라/보정 설정만
   자동 저장합니다. 사진·임베딩·Mesh·등록 DB는 저장하지 않습니다.
   미완성 단계는 파일을 덮어쓰지 않습니다.
5. **보정 테스트**를 누릅니다. 같은 **정면 → 좌 → 우 → 위** 요청을
   수행하고, 각 자세를 0.4초 이상·3프레임 이상 유지하면 자동 확인합니다.
   테스트에서는 P 키가 필요 없습니다. 요청과 다른 자세, 얼굴 소실, 입력 지연은
   유지 기록을 초기화하며 5개를 모두 통과해야 완료합니다.

왼쪽이 30도, 오른쪽이 60도로 측정되어도 각 방향의 실측 기준을 별도로
기록합니다. 정면과 방향별 기준 사이의 거리에 맞춰 비교 범위를 정하고,
중간 자세나 기준에서 너무 먼 자세는 판정을 보류합니다. 카메라/해상도/좌표
보정 설정이 같은 경우 저장값을 다시 불러올 수 있습니다. 사용자나 카메라
위치가 바뀌면 보정을 다시 시작하세요. 파일은 Git에서 제외합니다.

**고급 각도** 탭에는 기존 수동 임계값 입력과 정면 기준만 설정하는 방식도
남아 있습니다. 기존 방식의 `임계값 저장`은 `guided_capture.json`을 바꾸며,
P 키 방식의 개인별 4방향 보정 파일과는 별개입니다.
**좌표 안정화** 탭에서는 하늘색 원(원본)과 초록 십자(자동 보정)를 비교하고
보정 세기를 바꿀 수 있습니다. 좌표 처리 방식이 바뀌면 P 키 보정도 다시 해야 합니다.

눈·코끝·입꼬리 위치를 직접 맞추려면 **고급 점 조정** 탭을 사용하세요.

1. 정면에서 점이 안정적으로 검출된 상태에서 **수동 위치 조정 · 영상 정지**를 누릅니다.
2. 정지 영상의 노란 점 5개를 드래그합니다. 화면 기준 왼쪽/오른쪽 눈,
   코끝, 왼쪽/오른쪽 입꼬리로 이름을 표시하고 좌표 표를 함께 갱신합니다.
   점을 선택한 뒤 방향키로 움직이면 FHD에서도 원본 영상의 1픽셀씩 조정합니다.
3. **조정 적용 · 실시간 복귀** 후 정면 기준을 다시 설정합니다. 위치 차이는
   얼굴 상자 크기에 대한 비율로 적용해 얼굴 이동·크기를 따라갑니다.
4. **조정 취소**는 적용 전 변경만 버립니다. **자동 검출로 초기화**는 기존
   수동 보정도 지웁니다. 조정 중 얼굴을 잃거나 입력이 끊기면 적용할 수 없으며,
   취소하고 다시 시작해야 합니다. 이때 기존 수동 보정도 폐기합니다.

수동 조정 중에는 화면과 방향 판정을 멈추고 카메라 연결·얼굴 존재만 확인합니다.
눈/입꼬리의 좌우가 뒤바뀌거나, 정면에서 눈·코·입의 위아래 순서가 뒤집히거나,
자동 검출 위치에서 얼굴 크기의 30%를 초과하면 적용하지 않습니다.
수동 보정은 위치 차이를 더하는 시험 기능이며 새 특징점을 추적하는 모델은 아닙니다.
수동 값은 파일/DB에 저장하지 않고, 얼굴 소실·카메라 변경·중지 시 초기화합니다.

화면은 `정면 기준각도`, `좌우각도`, `상하각도`, `고개 기울임` 등 한글로 표시합니다.
원본·자동 보정·수동 보정·정면 기준 보정 값을 구분하며 각도/좌표의 소수점은
표시하지 않습니다. 각도 입력도 정수 단위입니다. 내부 계산과 판정은 원래
정밀도를 사용하며, 유지 시간·반응 시간 같은 초 단위 설정은 소수점을 유지합니다.

좌표 보정은 최근 3프레임의 중앙값을 구한 뒤 시간 간격에 맞춰 부드럽게
따라갑니다. 실제 움직임이 커지면 반응을 빠르게 합니다. 기본 반응 시간은
0.18초이며, 크게 설정하면 더 부드러운 대신 방향 전환에 늦게 반응합니다.
한 점의 비정상적인 이동은 얼굴 폭의 12%를 기본 제한으로 제외하고,
얼굴 전체의 이동도 검사합니다. 튄 프레임에서는 이전 보정 좌표를 출력하지
않으며 새 연속 3프레임을 기다립니다. 얼굴 소실·다중 얼굴·신뢰도 미달·
긴 입력 간격·해상도 변경·얼굴 위치 급변 시 좌표와 영점도 초기화합니다.
새 프레임이 오지 않는 경우에도 입력 지연을 감지해 이전 판정과 보정 점을 지웁니다.
좌표 보정값은 **적용 / 영점 초기화** 버튼으로 바꾸며 파일에는 저장하지 않습니다.

이 도구는 실제 처리와 같은 `yunet_pose`, `direction_matches`, `GuidedCapture`를
사용합니다. YuNet만 실행하고 사진·임베딩·Mesh·등록 DB를 저장하지 않으며
출입 처리를 하지 않습니다. 저장 버튼을 누르기 전에는 설정 파일도 바꾸지
않고, 저장 시 Mesh 임계값·인증 시간 제한 등 다른 설정은 보존합니다.

## DB와 파일

DB는 `stages/data/faces.sqlite3`입니다. 처음 실행할 때 필요한 테이블·열을
추가하며 기존 등록자와 관측 기록은 보존합니다.

| 테이블 | 내용 |
|---|---|
| `people` | 이름, 12개 임베딩의 대표값, 샘플 수, 갱신 시각 |
| `directional_samples` | 등록자·방향·방향 내 번호, 사진 JPEG, 임베딩, 원본/정규화 Mesh, 상대 각도, 영상 크기, Mesh 모델 ID, 자동/수동 촬영 여부 |
| `face_grids` | 방향별 대표 468점 입체 좌표, 대표 임베딩, 사진 수 3, 보정 기준·모델 버전 |
| `face_models` | 통합 468점 입체 좌표, 대표 임베딩, 원본 방향 수 5, 삼각형 연결 버전, 방향별 통합 오차 |
| `observations` | 인증된 두 사진과 임베딩, 방향, grid/통합 모델의 비교 오차·버전, 공통 인증 세션 ID |

`camera_session.py`는 등록/인증 처리부의 생성·종료와 배타적 단계 전환,
`enrollment.py`는 FHD 등록 전용, `pipeline.py`는 인증·미리보기·이탈 확인,
`photo_capture.py`는 같은 촬영 사진의 임베딩·Mesh 분석,
`guided_capture.py`는 방향 추정·촬영 조건·Mesh 비교,
`landmark_filter.py`는 테스트 도구의 5점 좌표 안정화,
`manual_landmarks.py`는 테스트 도구의 수동 점 조정과 얼굴 크기에 따른 위치 보정,
`pose_calibration.py`는 P 키 4방향 기준 수집·저장·개인 기준 판정·안내 테스트,
`pose_defaults.py`는 이름 있는 기본값과 실제 등록·인증의 좌표 안정화/기준 보정,
`face_grid.py`는 방향별 grid·통합 모델 생성·비교·미리보기를 담당합니다.
`face_topology.json`은 MediaPipe의 468점 연결 정보이며 저해상도 대기에서
추가 모델을 불러오지 않도록 정적으로 포함했습니다. 출처·라이선스는
`third_party/MEDIAPIPE_NOTICE.txt`, `third_party/MEDIAPIPE_LICENSE.txt`에 있습니다.
`liveness.py`는 촬영 사진의 Mesh 추출, `database.py`는 원자적 저장과 비교를
담당합니다. 미리보기 화살표는 `app.py`, 콘솔 미리보기는 `integrate.py`에 있습니다.
