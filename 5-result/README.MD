# 1~4단계 통합 · 5방향 얼굴 등록과 두 사진 인증

이 폴더의 카메라·검출·임베딩·DB 통합 흐름을 유지하면서 등록과 인증을
방향별 사진 방식으로 변경했습니다. 기존 `5-result.py`의 결과 처리 연결은
유지합니다. 이번 변경은 `5-result`에 적용하며 `6. rasberry pi`는 별도 실행본입니다.

## Windows 실행

처음 설치는 `setup.bat`, 이후 실행은 `run.bat`입니다. 가상환경과 모델 다운로드는
기존 방법을 사용합니다. 앱을 열고 **카메라 시작 → 사용자 등록 탭**으로 이동하세요.
Python 3.12 이상을 사용하는 기존 Windows 실행 환경을 기준으로 합니다.

1. 정면 얼굴로 촬영 준비 조건을 통과한 뒤 이름을 입력하고 등록을 누릅니다.
2. 화면의 화살표에 따라 **정면 → 위 → 아래 → 화면 왼쪽 → 화면 오른쪽**을 봅니다.
3. 각 방향에서 **3장씩**, 총 **15장**을 채택합니다. 진행 수와 방향을 화면에 표시합니다.
4. 15장을 모두 모은 뒤 사진·Mesh·임베딩을 한 번에 DB에 저장합니다.
5. 인식·기록 탭에서는 무작위로 요청한 서로 다른 두 방향을 보고 인증합니다.

예전 방식으로 등록한 이름과 대표 임베딩은 삭제하지 않습니다. 다만 방향별
사진·Mesh가 없으면 인증을 통과시키지 않고 **5방향 재등록**을 안내합니다.

## 처리 순서

```text
1. YuNet 절전 대기 (set1.json, 기본 320×180 / 5FPS)
2. 정면 준비 통과 → 활성 해상도 (640×480 / 목표 20FPS)
3. YuNet의 눈·코·입 5점으로 고개 회전을 추정하고 화살표 안내
4. 요청한 방향에서 일정 시간 유지하면 후보 프레임을 복사해 사진으로 고정
5. 그 사진에만 SFace 임베딩과 Face Mesh 연산
6. 방향·각도·사진 Crop·임베딩·원본 Mesh·정규화 Mesh를 연결
```

회전 중에는 Face Mesh를 계속 실행하지 않습니다. 모델 객체는 재사용하되
방향 조건을 통과한 촬영 사진에서만 추론합니다. 두 특징 모델은 같은 고정
사진을 처리하므로, 임베딩과 Mesh가 서로 다른 프레임에서 나오는 일을 막습니다.
등록·인증의 방향 검사는 standby의 정면 조건과 분리되어 있습니다.

YuNet 자체가 각도를 출력하는 것은 아닙니다. 5개 특징점에 일반적인 얼굴
모형과 근사 카메라 행렬을 적용하는 `solvePnP`로 **회전각을 추정**합니다.
사람과 카메라 높이에 따른 오차를 줄이기 위해 준비된 정면을 기준 자세로
보정하고, 이후 상대적인 회전각으로 각 방향을 판단합니다. 표시 각도는
실측 각도가 아니며 실제 카메라에서 조정해야 합니다.

## 인증

```text
정면에서 대표 임베딩으로 등록자 후보 확인
  → 정면·상·하·좌·우 중 서로 다른 두 방향을 무작위 선택
  → YuNet으로 방향·연속 추적 확인
  → 각 방향에서 사진 한 장을 고정하고 Mesh·임베딩 계산
  → 같은 등록자의 같은 방향 샘플 3장과 각각 비교
  → 두 사진 모두 임베딩·Mesh·상대 Z 오차 조건을 만족하면 성공
  → DB에서 최신 등록 정보로 재검사하고 인증 사진 2장을 함께 저장
  → 기존 결과 처리 모듈로 성공/실패 전달
```

첫 사진만 통과해서는 성공하거나 관측 사진을 저장하지 않습니다. 두 사진의
DB 기록은 같은 `auth_session` 값으로 묶입니다. 비교와 두 기록의 저장은
하나의 트랜잭션에서 수행해 도중 등록 변경·삭제와 부분 저장을 방지합니다.
인증 사진을 시간 간격으로 하나씩 저장하던 설정은 화면에서 제거했습니다.

Mesh는 원본 478점의 `(x,y,z)`를 저장하고, 비교에는 얼굴 468점을 사용합니다.
영상 비율을 반영한 뒤 위치·눈 사이 크기를 정규화하고 강체 회전을 정렬하여
같은 방향의 등록 형상과 RMS 오차·상대 Z 오차를 비교합니다. 임의의 비선형
변형으로 얼굴 형상이나 깊이를 맞추지는 않습니다.

**Mesh의 Z는 RGB 영상에서 추정한 상대 값입니다.** 이 비교는 실제 깊이 센서나
검증된 위조 방지 기능을 대체하지 않습니다. 기울인 사진·구부린 사진·재생 영상·
실시간 합성이 통과하지 않는지는 실제 카메라에서 별도로 검증해야 합니다.

## 설정과 오류 복귀

설정은 `stages/guided_capture.json`에서 변경합니다. 기존 회전 검사 설정인
`liveness.json`은 새 설정으로 교체했습니다.

- 정면: 기준 자세에서 yaw/pitch 각각 ±12도.
- 좌우: 상대 yaw 15~35도. 상하: 상대 pitch 12~30도.
- 최소 3프레임·0.25초 유지, 촬영 간격 최소 0.4초.
- 등록 전체 120초·방향당 25초. 인증 전체 25초·방향당 10초.
- 추적 간격 0.7초 초과, 여러 얼굴, 얼굴 소실, 급격한 위치 변화는 실패 처리.
- `yaw_sign`, `pitch_sign`으로 카메라에서 방향 안내가 뒤집히는 경우 보정.
- `mesh_limit=0.12`, `depth_limit=0.08`은 눈 사이 거리로 정규화한 시작값.
  실제 이용자·공격 샘플로 임계값을 검증해야 합니다.

등록 취소·화면 전환·카메라 중지 시 미완성 샘플은 메모리에서 폐기합니다.
다른 얼굴의 임베딩이 섞이면 중단합니다. DB 저장 중 오류가 발생해도 기존
등록 정보가 부분적으로 교체되지 않도록 롤백합니다. 성공·실패 결과는
한 번만 전달하고, 화면 전환 후 예전 세션의 결과는 사용하지 않습니다.

## DB와 파일

DB는 `stages/data/faces.sqlite3`입니다. 처음 실행할 때 필요한 테이블·열을
추가하며 기존 등록자와 관측 기록은 보존합니다.

| 테이블 | 내용 |
|---|---|
| `people` | 이름, 15개 임베딩의 대표값, 샘플 수, 갱신 시각 |
| `directional_samples` | 등록자·방향·방향 내 번호, 사진 JPEG, 임베딩, 원본/정규화 Mesh, 상대 각도, 영상 크기, Mesh 모델 ID |
| `observations` | 인증된 두 사진과 임베딩, 방향, 비교 점수·형상/Z 오차, 공통 인증 세션 ID |

`pipeline.py`는 처리 단계, `guided_capture.py`는 방향 추정·촬영 조건·Mesh 비교,
`liveness.py`는 촬영 사진의 Mesh 추출, `database.py`는 원자적 저장과 비교를
담당합니다. 미리보기 화살표는 `app.py`, 콘솔 미리보기는 `integrate.py`에 있습니다.


사용, 두 사진 모두 통과해야 인증, DB 롤백·재등록·삭제, 방향 화살표, 세션 취소,
추적 소실·시간 초과를 확인합니다. 실제 사람의 고개 회전, 카메라 지연과 위조
공격의 통과/거절률은 모의 테스트로 입증되지 않으며 실기기 확인이 필요합니다.
